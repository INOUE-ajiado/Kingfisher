# Kingfisher カラーパレット（色指定）管理・データ構造仕様書

## 1. データ構造設計 (JSON Schema)
キャラクターごとの色指定を厳密に管理するため、パレットデータは階層構造を持たせます。

*   **PaletteSet**: 1キャラクター分のパレット全体（例：「主人公」）
*   **Category**: 状態ごとの分類（「ノーマル」「1影」「ハイライト」）
*   **ColorItem**: 実際のパーツ色（「髪」「肌」「服」など）

```json
{
  "characterId": "hero_01",
  "name": "主人公_基本",
  "categories": [
    {
      "id": "normal",
      "name": "ノーマル",
      "colors": [
        { "id": "skin", "name": "肌", "rgba": [255, 228, 181, 255] },
        { "id": "hair", "name": "髪", "rgba": [255, 215, 0, 255] }
      ]
    }
  ]
}
```

## 2. スポイト（色取得）と登録の挙動
アニメ彩色特有の最速ワークフローを実現するためのUI仕様です。

*   **色の取得**: `Alt + 左クリック` でキャンバス上のピクセル色を取得し、現在のアクティブカラーに設定。
*   **色の登録**: カラーチャートの空きセル上で `右クリック`（または `Ctrl + クリック`）することで、現在のアクティブカラーをパレットに即座に保存。
*   **パレット切り替え**: 「ノーマル」「影」などのタブはショートカット（例: `1`, `2`, `3`）で瞬時に切り替え可能とする。

## 3. データの永続化とインポート/エクスポート
*   **ローカル保存**: Zustandの永続化ミドルウェア（`persist`）を使用し、ブラウザの `IndexedDB` にパレットを自動保存。
*   **ファイル共有**: 制作チーム間で色指定を共有するため、上記JSON構造を `.kfc` (Kingfisher Color) または汎用的な `.json` 形式でエクスポート・インポートする機能を実装。
