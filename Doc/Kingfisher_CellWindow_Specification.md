# Kingfisher セルウィンドウ（画像表示画面）機能詳細仕様書

アニメーションの彩色・リテイク作業において、修正前後のセルを並べて比較するための「2画面分割表示（スプリットビュー）」および「連動ナビゲーション」に関する詳細な仕様を定義します。

---

## 1. 画面構成・レイアウト設計

従来の「1画面表示」に加え、キャンバス領域を左右に分割する「2画面分割表示」モードを実装します。

### 1.1. 表示モード
* **単一ビューモード (Single View)**: 通常のペイント作業用。1つのTGAファイルを画面全体に表示する。
* **分割ビューモード (Split View / 2画面)**: 
    * 画面を左右に50%ずつ分割し、それぞれ独立した画像を表示する。
    * **主目的**: 左画面に「リテイク前（または原画）」、右画面に「リテイク作業中（彩色データ）」を表示し、見比べながら作業を行う。

### 1.2. アクティブウィンドウの概念
分割ビューモード時、ユーザーのキーボード入力（ショートカット）やペイント操作の対象を決定するため、**「アクティブウィンドウ」**の概念を導入します。
* クリックした側のビューがアクティブになり、タイトルバーの色（または枠線）がハイライト（カワセミブルー `#2563EB`）されます。
* ブラシやバケツなどのペイントツールは、アクティブなウィンドウに対してのみ作用します。

---

## 2. コントロールと連動（同期）機能

2画面表示時の最大の強力な機能として、左右のウィンドウの「ページ送り」や「表示位置」を同期させるリンク機能を実装します。

### 2.1. 独立操作モード（リンクOFF）
* **ページ送り**: アクティブなウィンドウに対してのみ、`PageDown` (次へ) / `PageUp` (前へ) が適用される。
    * 例: 左画面で`0001.tga`を見ながら、右画面では`0005.tga`を開くことが可能。
* **ズーム・パン**: マウスホイールや手のひらツールによる拡大縮小・移動は、操作した側のビューのみに適用される。

### 2.2. 連動操作モード（リンクON）
リテイク比較作業を最速化するためのモードです。ビューの上部ヘッダーにある「連動（鎖アイコン 🔗）」ボタンをONにすると、以下の操作が左右のウィンドウで完全に同期します。

* **連動ページ送り (Sync Navigation)**:
    * `PageDown` を押すと、左右のウィンドウ**両方**が、それぞれのフォルダリストの「次のファイル」へ同時に遷移する。
    * 例: 左画面が `A_part/0002.tga`、右画面が `A_part_retake/0002.tga` を開いている状態で「次へ」を押すと、左は `0003.tga`、右は `retake/0003.tga` へロード時間0msで同時に切り替わる。
* **連動ズーム・パン (Sync Viewport)**:
    * 片方の画面でズームインやドラッグ移動（手のひらツール）を行うと、もう片方の画面も全く同じ座標・倍率へリアルタイムに追従する。
    * 修正箇所（例：キャラクターの目のハイライト）をピンポイントで拡大比較する際に必須の機能。

## 3. UIコンポーネント詳細（セルウィンドウヘッダー）

セルウィンドウのタイトルバー（またはタブ領域）には、以下のUIコントロールを配置します。

| UI要素 | アイコン・見た目 | 機能詳細 |
| :--- | :--- | :--- |
| **分割トグル** | 🗗 (Split) | 1画面 ⇔ 2画面 分割を切り替える。 |
| **連動トグル** | 🔗 (Link) | ※2画面時のみ有効。左右のナビゲーション・ズームの連動ON/OFF。 |
| **ファイル名タブ** | `0001.tga` | 各ビューに表示中のファイル名。クリックでファイル選択メニュー。未保存の変更がある場合は `*` を付与。 |
| **倍率表示** | `150%` | 現在のズーム倍率。 |

## 4. 状態管理設計 (Zustand Store Schema)

2画面それぞれの状態と、連動状態を管理するためのデータ構造です。

```typescript
// store/useCanvasStore.ts
interface ViewportState {
  fileHandle: FileSystemFileHandle | null;
  currentIndex: number;
  zoom: number;
  pan: { x: number, y: number };
}

interface CanvasStore {
  // 表示モード
  isSplitView: boolean;
  syncMode: boolean; // 連動（リンク）モードON/OFF
  
  // どちらの画面がアクティブか (0: 左, 1: 右)
  activeViewIndex: 0 | 1;

  // 左右のビューそれぞれの状態
  views: [ViewportState, ViewportState];

  // Action例: ページ送り
  nextPage: () => void;
}
```

## 5. イベントハンドリング・ロジック (PageDown実行時)

キーボードショートカット `PageDown` が押下された際の中央制御ロジックです。

1. **`isSplitView == false` の場合**: 
   現在の単一ビューで次の画像をプリフェッチバッファからロード。
2. **`isSplitView == true` かつ `syncMode == false` の場合**: 
   `activeViewIndex` を確認し、アクティブな側（左または右）の画像のみを次へ進める。
3. **`isSplitView == true` かつ `syncMode == true` の場合**: 
   Workerスレッドに「左ビューの次画像」と「右ビューの次画像」の両方のバッファポインタを要求。
   GPU上で、左側のテクスチャと右側のテクスチャを同時にスワップ（更新）し、再描画を行う。

---

## 6. WebGPU レンダリング仕様

* **キャンバス**: HTMLの `<canvas>` 要素は1つだけ配置する（パフォーマンス最適化のため、DOMを2つに分けない）。
* **シザーテスト (Scissor Test)**: WebGPUの `setScissorRect` コマンドを使用し、キャンバスの左半分にView[0]のテクスチャを、右半分にView[1]のテクスチャを描画する。
* これにより、2画面表示であってもCPU/GPUのオーバーヘッドを最小限に抑え、**両画面同時の60fps描画**を完全に保証する。
