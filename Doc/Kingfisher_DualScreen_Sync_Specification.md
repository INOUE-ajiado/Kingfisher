# Kingfisher ファイルブラウザ・2画面連動（リテイク比較）詳細仕様書

**Document Version:** 1.0 (File Browser & Sync Spec)
**Target Feature:** 2画面比較時のファイルブラウザ制御とナビゲーション連動

---

## 1. 背景とUI設計の工夫（省スペース化）

2つのウィンドウ（A: 修正前、B: 修正後）で別々のフォルダを参照する場合、ファイルブラウザを2つ表示するとキャンバスの作業領域を圧迫してしまう。
アニメ制作においては「修正前と修正後でファイル名（連番）が一致する」という特性を利用し、**「1つのパネル内に統合されたファイルリスト」**を設計することで、省スペース化と視認性の向上を両立する。

### 1.1. ファイルブラウザのUI構成（統合リストビュー）
パネル上部に「リンク（連動）ボタン」と「各ウィンドウの参照フォルダパス」を配置し、リスト部分はファイル名ベースで1列に統合する。

* **UIイメージ（アスキーアート）:**
  ```text
  [ ファイルブラウザ ]
  [ 🔗 連動 (Link) ON ]  [ A: ｱｸﾃｨﾌﾞにする ] [ B: ｱｸﾃｨﾌﾞにする ]
  Dir A: /Cut001_Original/
  Dir B: /Cut001_Retake/
  -------------------------------------------------------
  ファイル名      | Win A の状態     | Win B の状態
  ▶ 0001.tga    | [済] 0001.tga    | [編] 0001.tga
    0002.tga    | [済] 0002.tga    | [  ] (ファイルなし)
    0003.tga    | [済] 0003.tga    | [済] 0003.tga
  ```

## 2. 連動（リンク）機能の詳細仕様

ファイルブラウザ上部にある「🔗 リンク（連動）」ボタンのON/OFFによる挙動の違いを定義する。

### 2.1. リンクON（連動モード）時の挙動
修正前後のセルを同時に進めながら比較するためのモード。

* **キーボード操作 (下キー / PageDown):**
    * フォルダウィンドウ上で「下（↓）」を入力、またはショートカット「PageDown」を押下すると、**ウィンドウAとウィンドウBの両方が同時に次のセル（例: `0002.tga`）へ遷移**する。
* **リストのクリック操作:**
    * ファイルブラウザのリストから `0003.tga` をクリックすると、ウィンドウAは `Dir A/0003.tga` を、ウィンドウBは `Dir B/0003.tga` を同時にロードし表示する。
* **ズーム・パン（オプション連動）:**
    * （※キャンバス側の仕様と連携し）画面の拡大率や手のひらツールによる移動も両画面で完全に同期する。

### 2.2. リンクOFF（独立モード）時の挙動
特定の画面だけを別のセルに移動して確認したい場合（例：A画面は原画の`0001.tga`に固定し、B画面だけ彩色データを進める等）のモード。

* **アクティブウィンドウの判定:**
    * リンクOFF時は、ウィンドウAまたはBのどちらか一方が「アクティブ」となる（キャンバスをクリックするか、UI上のボタンで切り替え）。
* **キーボード操作 / クリック操作:**
    * 「下（↓）」や「PageDown」の入力、またはリストのクリック操作は、**現在アクティブなウィンドウ（例：ウィンドウBのみ）に対してだけ適用**される。ウィンドウAの表示は切り替わらない。

## 3. 例外処理・エッジケースの仕様

### 3.1. 片方のフォルダにファイルが存在しない場合（欠落ファイル）
* **シナリオ**: オリジナル（Dir A）には `0002.tga` があるが、リテイク（Dir B）にはまだ `0002.tga` が作成されていない場合。
* **連動モード時の挙動**: 
    * ウィンドウAは正常に `0002.tga` を表示する。
    * ウィンドウBは黒（または専用のチェッカーボード背景）になり、「File Not Found」または「NO DATA」の透かしテキストをキャンバス上に表示する。
    * エラーでアプリケーションを停止させず、そのまま比較や次のセルへの遷移を継続できるようにする。

### 3.2. 保存時の挙動（上書き保存）
* 連動モード中に `Ctrl + S`（保存）が実行された場合、**アクティブとしてフォーカスされている側のキャンバス（通常はリテイク作業を行っているウィンドウB）のデータのみ**を上書き保存する。
* 比較用のオリジナルデータ（ウィンドウA）を誤って上書きしないよう、保存対象を厳密に分離する。

## 4. 状態管理（Zustand Store）の実装方針

統合リストビューと連動機能を実装するためのステート管理構造。

```typescript
interface FileBrowserStore {
  // 連動設定
  isLinked: boolean;
  
  // フォルダパス管理
  dirA: FileSystemDirectoryHandle | null;
  dirB: FileSystemDirectoryHandle | null;
  
  // 統合されたファイル名リスト（Dir AとDir Bの和集合をソートしたもの）
  unifiedFileList: string[];
  
  // 現在のインデックス（リンクON時は共有、OFF時は別々に管理も可能だが、
  // UIのリストハイライト用にはメインインデックスを1つ持つ）
  currentIndex: number;
}
```

## 5. バックグラウンド先読み（プリフェッチ）の最適化
連動モード（リンクON）の場合、ユーザーが現在のセルを閲覧している裏で、Web Workersは **「Dir Aの次のファイル」と「Dir Bの次のファイル」の両方を同時にデコード** し、GPUのテクスチャメモリ（SharedArrayBuffer）にスタンバイさせる。
これにより、下キー（↓）を押した瞬間に、2画面のフルHD/4K画像がロード時間0msで同時に切り替わる「ネイティブ超え」のユーザー体験を実現する。
