## 1. プロジェクト概要

### 1.1. システムの目的
本システム「Kingfisher」は、アニメーション制作における彩色（仕上げ）工程をブラウザ上で完結させる、完全フロントエンド動作の高機能・超高速Webアプリケーションである。
既存のオンプレミス型デスクトップアプリケーション（RETAS STUDIO PaintMan等）と同等の操作感・機能を再現しつつ、最新のWeb技術（WebAssembly, WebGPU, File System Access API）を駆使することで、旧来のソフトを凌駕するレンダリング速度とファイル処理速度を実現する。

### 1.2. コンセプト
カワセミが水面に向かって一直線に、かつ正確に獲物を捕らえる姿にインスピレーションを得た**「無駄を省いて最速で狙った領域を塗りつぶす」**プロフェッショナル向け彩色ツール。

## 2. デザイン・UI/UX設計

### 2.1. コンセプトカラー（カラーパレット）
スタイリッシュでクリーンな「ホワイト」を基調とし、UIのアクセントやステータス表示に以下のカワセミカラー（コンセプトカラー）を適用する。

#### 背中の青（カワセミブルー・コバルトブルー系）
* **鮮やかな青 (#2563EB):** 光沢のある鮮やかな青。アクティブなツールやプライマリアクション。
* **深みのある青緑 (#38B48B):** 翡翠色。セカンダリアクセント、成功ステータス。
* **ピーコックブルー (#009E9F):** ホバー状態、ローディングインジケーター用。

#### お腹のオレンジ（橙色・黄土色系）
* **鮮やかなオレンジ (#F97316):** 重要なアクション（保存、次セルへの移動ボタン）用。
* **黄土色・濃い橙 (#D97706):** 注意喚起、警告ステータス用。

### 2.2. 画面構成（マルチウィンドウUI）
キャンバスを中心に、ドッキング可能な以下のパネル群を配置する。各パネルはフラットでミニマルな境界線により区切られる。

| パネル名 | 役割・機能 |
| :--- | :--- |
| **セルウィンドウ (Canvas)** | メイン描画領域。TGA画像の表示およびペイント操作を行う。 |
| **ツールパレット** | バケツ（フィル）、閉領域フィル、ブラシ等の各種ツールを選択する。 |
| **ツールオプション** | 隙間閉じピクセル数、含み塗り（色トレス線）のON/OFFなどの詳細設定。 |
| **カラーチャート** | キャラクターごとのインデックスカラー（ノーマル、影等）の管理・登録。 |
| **ファイルブラウザ** | 対象フォルダ内の連番TGAファイルリストを表示し、即座に切り替える。 |
| **ライトテーブル** | 前後のフレーム（セル）を半透明で重ねて表示するオニオンスキン機能。 |

## 3. システム・アーキテクチャ

本システムは、サーバーへのデータアップロードを一切行わず、ユーザーのローカルマシンリソースを最大限に活用する**「ゼロ・アップロード・アーキテクチャ」**を採用する。

| 処理レイヤー | 採用技術・アプローチ |
| :--- | :--- |
| **ファイルI/O** | **File System Access API** により、ローカルフォルダからTGAバイナリを直接メモリへ読み込む。 |
| **デコード処理** | **WebAssembly (Wasm) + SIMD** を利用し、CPUのベクトル演算でTGA展開をネイティブ速度で処理。 |
| **並行処理** | **Web Workers** でメインスレッドから切り離し、連番ファイルのバックグラウンド・プリフェッチを実行。メモリ共有には `SharedArrayBuffer` を使用。 |
| **レンダリング** | **WebGPU** (または WebGL 2.0) により、デコードされたピクセル配列をGPUテクスチャとして直接描画。 |

## 4. 採用技術スタック

### 4.1. フロントエンド（UI・全体制御）
* **言語:** TypeScript
* **フレームワーク:** React
* **ビルドツール:** Vite
* **状態管理:** Zustand

### 4.2. コアエンジン（画像処理・アルゴリズム）
* **言語:** Rust
* **出力形式:** WebAssembly (Wasm)
* **役割:** TGAバイナリ解析、独自バケツ塗り（Flood Fill）アルゴリズムの高速実行。

### 4.3. ホスティング（インフラ）
* **プラットフォーム:** Firebase Hosting
* **必須要件:** `SharedArrayBuffer` を有効化するため、`firebase.json` にて `COOP (Cross-Origin-Opener-Policy)` および `COEP (Cross-Origin-Embedder-Policy)` ヘッダーを出力するよう構成。

## 5. コア機能要件

1. **独自仕様の透過処理:** 完全な白（RGB: 255, 255, 255）を透明色（アルファ値0）としてレンダリングする。
2. **含み塗り（自動色トレース）:** 赤・青・緑などの「色トレス線」を判定し、バケツ塗りの際に境界線そのものも塗りつぶす領域拡張アルゴリズム。
3. **隙間閉じ（Gap Closing）:** 線画の数ピクセルの途切れを検知・無視し、意図しない「液漏れ」を防ぐ機能。
4. **閉領域フィル:** 投げ縄ツールで囲んだ領域の内側にある空白ピクセルを一括で塗りつぶす機能。
5. **超高速連番ナビゲーション:** ショートカットキー押下時、プリフェッチ機能によりロード時間0msで次のTGAファイルへ切り替える。

---

## 6. 非機能要件・パフォーマンス目標

* **レンダリング性能:** 巨大なTGA画像（4K相当等）のパン・ズーム・レイヤー合成において、常時 60fps を維持すること。
* **ネットワーク依存からの脱却:** アプリケーションロード後、画像の読み込みや編集において一切の通信を発生させないこと。
* **セキュリティ:** 画像データはブラウザのメモリ内およびユーザーのローカルディスクにのみ存在し、外部サーバーへは送信されない構造を保証すること。
